# Agent Note: 按成果绑定的能力组合

Status: implemented

[English](2026-08-20-outcome-bound-capability-composition.md) | 中文

## Problem

能力以前可以命名成果并附加提供方工具，但无法说明让成果真正可执行所需的输入、资源、执行入口、审批和评估。选择能力会开放全部附加工具，因此本地第三方插件无法精确限定到某个承诺成果。

## Decision

每个能力成果都可以声明非秘密输入、所需资源槽、工具或已导出工作流入口、审批模式和评估资产 ID。选择能力时可以固定一个成果。会话会记录该成果，并开放 Harness 核心工具、全局附件和映射到所选成果的附件；仅映射到其他成果的工具会在当前会话和恢复后的会话中被拒绝。

Cordis 组合插件仍是扩展单元。本地配置可以安装 npm、Git、私有 SSH 或绝对路径插件，并在重启后激活其声明的补丁。Hyperlake CLI/MCP 是内置的受治理适配器。dbt 类插件和客户自有插件通过同一注册表贡献工具、资源发现、知识、工作流或评估，并从能力的“工具”界面附加。提供方标识和本地/平台执行路由保留在高级配置中。

Web 界面提供概览、成果、资源、工具、知识与资产、工作流、评估、访问和高级视图。成果使用结构化字段，不再使用竖线分隔的能力编辑器。

## Verification

能力包测试覆盖按成果限制工具可见性和持久选择来源。组件测试覆盖结构化创建、固定成果的使用、工作流展示、工具附加和插件安装。聚焦测试共 21 项并全部通过。

## Alternatives considered

**让每个已安装插件对所有能力可用。** 未采用，因为安装并不等于授予上下文相关性，过宽的可见性也会降低工具选择的可预测性。

**为本地插件创建 Rails 记录或独立市场服务。** 未采用，因为所需扩展路径是本地的，而 Cordis 已负责配置安装、激活和贡献发现。

**把完整成果契约写入自由文本描述。** 未采用，因为运行时无法验证引用，也无法执行按成果限制的工具可见性。

## Consequences

能力现在可以描述可执行结果，并在不让凭据或执行流经 Rails 的情况下封装 Hyperlake 与第三方插件。插件入口仍依赖其底层运行时执行授权和操作审批；能力元数据用于缩小组合范围，但不会替代目标系统策略。
