# Agent Note: 按成果绑定的能力组合

Status: implemented

[English](2026-08-20-outcome-bound-capability-composition.md) | 中文

## Problem

能力以前可以命名成果并附加提供方工具，但无法说明让成果真正可执行所需的输入、资源、执行入口、审批和评估。选择能力会开放全部附加工具，因此本地第三方插件无法精确限定到某个承诺成果。

## Decision

每个能力成果都可以声明非秘密输入、所需资源槽、工具或已导出工作流入口、审批模式和评估资产 ID。选择能力时可以固定一个成果。会话会记录该成果，并开放 Harness 核心工具、全局附件和映射到所选成果的附件；仅映射到其他成果的工具会在当前会话和恢复后的会话中被拒绝。

多个能力可以同时保持已配置和就绪，但每个会话只能在第一轮之前选择一个已就绪的能力和成果。输入框直接提供该选择，将其持久化到会话中，并在会话开始工作后锁定。能力卡片会显示该能力处于已禁用、需要设置、已就绪或当前会话已激活状态。

Cordis 组合插件仍是扩展单元。本地配置可以安装 npm、Git、私有 SSH 或绝对路径插件，并在重启后激活其声明的补丁。Hyperlake CLI/MCP 是内置的受治理适配器。dbt 类插件和客户自有插件通过同一注册表贡献工具、资源发现、知识、工作流或评估，并从能力的“工具”界面附加。提供方标识和本地/平台执行路由保留在高级配置中。

Web 界面提供概览、成果、资源、工具、知识与资产、工作流、评估、访问和高级视图。成果使用结构化字段，不再使用竖线分隔的能力编辑器。

资源设置从每个已声明资源槽开始。界面按兼容资源类型筛选已安装提供方，发现已经授权的资源，并通过一次操作附加和绑定所选不透明 ID。Hyperlake 适配器提供 Hyperlake 集群、SaaS Lake 环境、已部署 Agent、语义模型项目、受治理服务和监控器的发现能力。它把 MCP 工具注册为不可移除的安装级附件；凭据和目标授权仍由 Hyperlake CLI 与目标服务持有。自由输入资源编辑器仅用于没有发现提供方的额外插件上下文。

## Verification

能力包测试覆盖按成果限制工具可见性、持久选择来源、安装级附件和绑定清理。适配器测试覆盖内置资源提供方和共享 Hyperlake 工具注册。组件测试覆盖结构化创建、输入框选择、引导式发现和绑定、工作流展示、工具附加和插件安装。

## Alternatives considered

**让每个已安装插件对所有能力可用。** 未采用，因为安装并不等于授予上下文相关性，过宽的可见性也会降低工具选择的可预测性。

**为本地插件创建 Rails 记录或独立市场服务。** 未采用，因为所需扩展路径是本地的，而 Cordis 已负责配置安装、激活和贡献发现。

**把完整成果契约写入自由文本描述。** 未采用，因为运行时无法验证引用，也无法执行按成果限制的工具可见性。

**在每个会话中激活所有已就绪能力。** 未采用，因为重叠的成果和资源绑定会让目标选择产生歧义。就绪状态属于部署配置，激活状态属于单个会话。

**要求用户在通用表单中手工输入资源 ID、端点或凭据。** 未采用，因为已安装适配器可以通过其现有安全配置发现授权资源。不透明提供方 ID 保留授权边界，也避免复制秘密。

## Consequences

能力现在可以描述可执行结果，并在不让凭据或执行流经 Rails 的情况下封装 Hyperlake 与第三方插件。会话获得明确且持久的操作上下文，资源设置也不再要求用户理解提供方内部机制。插件入口仍依赖其底层运行时执行授权和操作审批；能力元数据用于缩小组合范围，但不会替代目标系统策略。未声明为共享附件或能力附件的已安装工具仍然可见，并会明确标记为不受能力管理，而不会被错误地描述为已经受限。
